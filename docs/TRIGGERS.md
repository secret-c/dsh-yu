# 独立触发器与随机自主任务

任务→触发器创建独立规则，再在任一任务详情“使用独立触发器”选择。规则按稳定ID引用，可供多个任务使用，编辑同步参数；每个任务有独立等待时刻、启停与运行历史。全局暂停不丢失任务自身的启用选择。移除任务中的引用不删定义；仍被引用的定义禁止删除。旧任务专用触发保留兼容，可按需换成独立规则。

随机自主与Roll点均可选泊松节奏（指数等待）或固定周期。minutes是指数分布平均等待分钟数/固定周期分钟数，范围1–10080；cooldownMinutes是最小冷却分钟数（至少1且不超过minutes）。指数等待取最大值max(冷却,指数抽样)，因此实际平均等待略大于设定分布均值。10秒轮询会带来最多约10秒调度延迟，队列拥堵可更晚。hours为运行时区小时窗口[start,end]，0≤start<end≤24；null全天，跨夜可拆成两个规则。候选时刻落在窗口外延到下一次开放，实际执行也复核窗口。

random到期直接执行；roll每次到期均匀掷1..sides（2–1000000），点数≤target才执行，命中率target/sides。失败也消耗本次槽位且记录审计，不反复重掷。暂停/启用或参数变化重新安排时刻；未变规则、刷新和重启保留已存时刻。停机错过的随机/roll事件跳过，无集中补跑。到期先持久化下一槽位再入队，防同一槽位重复；若进程恰在持久化后入队前中断，该次可丢失，不承诺exactly-once。

Webhook引用各任务有独立URL与限流；共享的是匹配参数，不是URL。消息触发仍按渠道既有优先匹配路径选任务，并不广播所有引用。定时与随机引用则各自调度。新的规则只有被任务选用后才可能运行；启用任务前检查目标、工具和模型费用。

配置文档settings["triggers.library"]保存定义库，tasks[].triggers[].spec.definitionId保存引用。导入引用按definitionId匹配，旧任务专用规则按type+label匹配。JSON检查拒绝未知定义ID和移除正在使用的定义；全清空同时清除库与任务引用，保留聊天、记忆等业务数据。Webhook口令属于实例凭据，默认导出省略，定义库从不存口令。
