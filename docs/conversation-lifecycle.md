# 任务会话与摘要接续

任务可以跟随消息来源、选择已有会话、新建固定会话，或每次新建。已有 `per-peer` / `reuse` / `new` 及会话 ID 保持兼容；任务详情页右侧的「任务会话」位于触发绑定上方。选择已有会话时按名称或来源搜索，列表显示更新时间，无需知道内部 ID。「新建固定会话」填写名称后点「创建并绑定会话」，立即创建，不调用模型；旧 API 的 `reuse` 加空 ID 仍在首次运行创建后回写。旧历史不会自动合并。会话在入队时确定，运行中修改绑定只影响之后入队的执行。已归档或不存在的固定会话会拒绝新运行，需明确恢复或重新选择。

任务目标和固定上下文说明分别每轮重新注入，包括多个任务共享会话和网页接续。静态上下文注入仍遵循资源绑定的 session / turn 配置。工具权限按当前执行计算，不能由历史目标授予。项目状态自动注入已停用，项目资料与进度通过工具读取。旧配置迁移见 [上下文方案说明](context-policy.md)。

“任务完成后关闭会话”独立于原来的“写入记忆归档”选项。字段为 `task.archivePolicy.conversation`，默认 `keep`；`on-success` 只接受每次新建模式。仅业务成功且该会话仍由当前任务独占、没有其他绑定或排队消息时，才在执行结束前关闭。宿主关闭失败时保留会话状态、会话 ID 与消息，运行步骤记录错误。任务产出成功与关闭失败分开显示。所有聊天记录保留。

任务会话卡片可直接开关长期模式，与会话绑定在同一事务中保存；也可在会话页显式开启，保存 `conversation.meta.continuity = { enabled: true, thresholdRatio: 0.8 }`。旧会话缺省关闭，继续遵循已有 `runtime.sessionRotation`；开启后跳过每日物理会话轮换。

Yu 在成功回合结束、仍持有会话执行锁时，使用该 agent 的宿主 `tokenMeter.measure` 与模型实际容量检查压力。达到阈值后调用宿主原生 `compaction.compactNow`，使用当前模型生成摘要并由宿主写入 checkpoint，保持逻辑和物理会话 ID。摘要只改变模型可见上下文，Yu 消息和宿主完整事件日志均不删除。压缩是有损摘要，不承诺无限或无损记忆，也不保证原文保留最近若干条。

阈值是 Yu 轮末补充检查的触发比例（0.5–0.9），同时受模型输出预算约束。宿主原本的自动压缩策略独立运行，可能更早触发；关闭 Yu 长期模式不会关闭宿主保护。摘要会调用当前模型，可能产生正常模型费用。安装验证不会主动调用付费模型。

能力缺失、容量未知、计量无基线、输出预算异常均显示 `unavailable`，不会假报摘要成功。没有安全可压缩区间显示 `no-span`；摘要失败显示 `failed`，五分钟内冷却，保留原始会话。当前摘要检查结果持久化于 `meta.continuityState`；成功包含 compaction ID 和源事件序号，每次执行步骤提供诊断。摘要内容与持久化恢复由 DSH 原生 checkpoint 负责，Yu 不把摘要作为新用户指令回灌。

配置 JSON 保留任务选择、固定会话 ID 和独立关闭策略；旧 JSON 省略会话 ID 时保留已有绑定，显式 null 清除绑定。固定引用的会话不存在或已归档时，导入提前报错，整个配置不写入；跨实例迁移需先重新选择当地已有会话，配置不会携带或自动合并聊天历史。会话策略与摘要状态属于业务数据，不随配置导入、替换或清空重建；配置导出不是完整会话备份。删除任务保留其运行和会话记录。按天或周自动归档未包含在本版本。

会话卡片有独立的保存入口，只提交会话方式、目标、成功归档策略和长期模式，不提交左侧未保存的目标、资源授权或其他草稿。新建与绑定失败时整体回滚。已有会话待选择时会话保存和基本表单保存均禁用。左侧保存不会覆盖卡片已保存的会话策略。

使用顺序：打开任务 → 右侧选择会话方式 → 选择名称或为新会话命名 → 保存会话设置 → 点击「打开会话」直接输入。跟随来源适合消息触发；已有会话适合接着聊；新建固定适合连续工作；每次新建适合彼此独立的任务。只有每次新建支持成功后自动归档。
